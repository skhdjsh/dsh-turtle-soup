# 海龟汤题库

装了这个插件，你的机器就是这套题的中心：题库、待审投稿、战绩都存在本机 `~/.dsh/turtle-soup/`。

## 玩法

- `turtle_draw`：抽一道题，按红/黑/清汤、本格/变格、难度区间筛。返回汤面、汤底、提示，以及这题最多能问几句（基础 10 句 + 每颗星 6 句）。
- 主持人（你或当前对话的模型）拿着汤底，只答「是」「不是」「跟这个没关系」「接近了」「猜对了」。
- 问满上限还没猜中，就揭晓。
- `turtle_stats`：把这一局的胜负、问了几句记进本地统计。

## 题库管理

- `turtle_bank`：总数、类型分布、平均难度、待审数量、战绩。
- `turtle_list` / `turtle_get`：分页浏览、看单题（**不返回汤底**，避免提前剧透）。
- `turtle_add` / `turtle_delete`：直接入库或删题。汤面最多 1500 字、汤底最多 3000 字，长题也能存。

## 别人交题：投稿码 + 审核

跨机器交题不需要服务器，走「投稿码」：

1. 对方拿到一道题，用 `turtle_export` 导出成一串 `TS1.…` 的投稿码（自带校验和，改一个字符就失效）；
2. 把码发给你；
3. 你用 `turtle_submit` 收进待审队列——**不会直接进题库**；
4. 用 `turtle_review` 看队列，`approve` 通过入库，`reject` 驳回。

装插件的人天然是管理员：只有他能加、删、审。投稿人只能生成码，碰不到你的题库。

## 题库共享

题库就是一份 JSON，因此有三种共享方式：

1. **投稿码**（上面说的）：一对一，最稳。
2. **文件/URL 同步**：`turtle_snapshot` 把整库导出成一段 JSON，贴到 Gist / GitHub raw / 网盘；别人或你自己用 `turtle_sync` 填直链拉取。合并按「标题 + updated 时间戳」：远端更新更晚才覆盖，删除以墓碑传播，本地更新更晚则保留本地并在结果里列成冲突。
3. **自建后端**：配套的 Cloudflare Workers + D1 代码（插件包同级的 `turtle-server/`），部署后 `turtle_online` 直接交题、待审、审稿、拉题。

## 限制（如实说明）

- **投稿码要靠人传**：微信/邮件/任何聊天工具都行，没有内置点对点通道。
- **抽题结果里有汤底**：工具结果在对话里可见，所以抽完题别让玩家翻那条工具卡片；要么由你当主持人，要么用另一个会话抽题，把汤面抄给玩家。
- 同一时间只维护一份本地题库，没有多用户权限分级；「管理员」就是装插件的那台机器。
- **后端代码未在真实 Cloudflare 账号上验证**：接口和字段按官方文档写，首次部署可能要调。
